# 小红书对标素材池筛选

## 任务契约
反复解决逐篇浏览搜索慢、按博主采集品类杂、只看高赞造成错选的问题。用户负责按搜索维度批量收集，Agent负责合并、去重、时间检查、品类判断、正文精筛。完成证据是总量可核对、每条有来源、入选有理由、缺失明确的筛选报告。

换客户只换客户基准和检索维度，不重新制作本Skill。它位于文案基准之后、最小改写之前；接下来可以交给 xhs-note-minimal-rewrite，再由 xhs-food-image-planning 按文配图。

## 输入与不变量
- 先读项目导航及对应客户事实。用户当前确认优先于旧规则；客户资料不写死在本Skill。
- 输入至少应有标题、正文或可读截图、来源链接/ID、发布时间、点赞量。收藏、评论、分享、采集时间、搜索词、作者、笔记类型和封面链接有则保留。
- 不把文件名导出日期、更新时间当发布时间。默认以任务当天向前推6个日历月；日期缺失进入待核实池，不伪造年份。
- 互动是采集快照。缺失不填0，万/k单位解析，带“+”保留近似性质。不推断自然流量、投流、销量和转化率。
- 原始表只读。来源文件、工作表、Excel行号随记录保留；同ID多次快照保留各来源，不随意拼最大互动值。
- 对标中的菜品、做法、活动、排名、位置、店龄和作者经历均不自动成为客户事实。

## 工作流程
1. **批量盘点**：先查文件/字段/日期/类型/作者分布和重复。标准社媒助手xlsx可用 [scripts/prepare_pool.py](scripts/prepare_pool.py) 生成JSON中间池；其他表头先映射，不静默丢字段。
2. **时间筛选**：半年内、超期、日期待核实分别统计。缺采集日期时按文件名识别只能标“文件名指示”，不装成已核实。
3. **广召回**：用客户品类、具体单品、场景及正文关键词召回；标题也全览一遍，防止模糊标题漏选。关键词只负责召回，不能直接当最终品类判定。
4. **先匹配后热度**：人工读候选完整正文，判断主角是门店还是饮料、零售、教程、活动。图文与视频分开；无正文不能推定是可改写正文，未看视频不得评价镜头或脚本。
5. **热度分层**：没有用户阈值时可试用1000赞以上、300—999赞、100—299赞、低于100赞四档，明确是工作分层而非平台标准；同品类内比较赞藏评分享，收藏率仅辅助。低赞但匹配保留观察池，不冒充热门。
6. **精筛与去同质化**：先产品重合，再正文需替换比例，再标题/语气，最后互动。分为优先参考、局部/标题备用、观察、淘汰/待核实。不同作者和不同钩子尽量兼顾，但不为配额降低适配度。保留强语气不擅自弱化；不能仅换地名就宣称整篇可用。
7. **交付**：总量与各阶段数量、入选清单、原题原链接、原始发布时间及互动、来源行号、参考位置、不可迁移信息、淘汰原因。保留可检索的全量审计池。对未人工审阅的记录写“初筛”，不谎称全量语义精读。

## 用户采集建议
每批100—200条，按品类词、单品词、场景词搭配多个城市搜索；优先图文和半年内，不只采少数作者。示例：牛肉火锅/鲜货烧烤；雪花牛肉/香辣蟹；大学城聚餐/下班宵夜/旅游晚餐。示例需替换为新客户真实经营范围。

先保留同品类，再挑高赞；同一爆款通过不同搜索命中不重复计数。保留搜索词和采集时间。采集动作不在本Skill自动展开，只有用户明确要求实时搜索时才补查原帖；本地材料足够则避免逐条联网。

## 边界
筛选不等于生成客户标题、改写、下载全部媒体、写入飞书或发布。缺数据可完成局部筛选并列缺口，不为了凑数量混入跨品类高赞。原稿保留在用户素材池，交付页面按需引用并标来源。

## 验证
用真实素材池运行一次主流程，核对输入输出记录守恒、边界日期、数值缺失、重复和失败路径。未做盲测只报告结构或行为冒烟，不声称留出通过。
