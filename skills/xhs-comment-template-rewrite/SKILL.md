# 小红书评论模板调用与最小改写

## 任务

根据用户选定的评论模板库记录，输出 A 主评论和 B–E 跟评的原文或最小替换稿。A 与 B–E 是两种角色：A 独立成主评；B–E 是回复 A 的跟评，可以按用户规则从同类模板交叉调用。优先精确调取，用户明确要求替换时才改动。

## 输入与前置检查

1. 读取本批评论模板库，并按 ID、原始文本、来源、审核状态、评论角色定位素材；不可只凭记忆或此前聊天片段代替当前库。
2. 若存在用户手动确认的案例库，优先读取并调用其中案例；未确认候选库只作补充，不覆盖用户确认库。
3. 读取目标品牌/门店基准及本次明确的替换要求。没有库记录时，请用户提供截图、链接、表格或原文；没有目标品牌映射时，只问缺少的最小信息。
4. 输出前检查模板来源是否可访问、原文是否完整、是否为 A 或 B–E、审核状态是否可调用。缺项标注，不补造。

## 改写规则

- **A 主评论**：优先按用户指定记录原样调用。用户要求替换品牌、品类或产品时，只做明确的一对一词项替换；每项替换都要有用户指令或目标品牌基准支持。保留句式、语气、标点、表情和强度，不新增卖点。
- **B–E 跟评**：默认直接从可调用记录中调取原文，不润色、不重写、不擅自把原品牌、产品、地点改成目标品牌信息。只有用户明确指定替换且有事实依据时，才按同样的一对一方式替换。
- B–E 可跨来源选取时，内部保留每条来源ID，并注明“跨来源模板组合”；不得把它描述成原平台上真实存在的同一评论链。
- 不将跟评人为分为老客/新客，除非原话明确说明且用户要求此标签。
- 用户明确要求“微改写”时，可以在保留模板骨架的前提下替换品牌、品类、门店、菜品或产品描述；菜品替换必须来自目标品牌评价、菜单、用户确认资料或当前任务给出的案例库。
- A 主评论尽量避免连续重复同一开头、同一强判断和同一产品细节；需要批量输出时，先从用户确认案例库分散选取，再用目标品牌证据做轻微替换。
- 模板与事实分开标记。涉及目标品牌的菜品、价格、地址、套餐、服务和体验承诺，必须能回到目标品牌资料、用户确认案例或本次明确指令；不能仅凭其他商家的模板原文当成目标品牌事实。

## 输出

用户只要文案时，按以下格式交付，不附创意备选：

```text
A：{按要求精确调用或最小替换的主评论}
B回复A：{库内跟评原文}
C回复A：{库内跟评原文}
D回复A：{库内跟评原文}
E回复A：{库内跟评原文}
```

默认在文案后用一行简短来源记录标出模板ID和可用状态；用户要求纯文案时可省去来源展示，但内部仍需保留映射。若原文不可直接用于目标品牌，说明具体缺少哪项事实证据，不输出伪装成真实消费者的替代稿。

## 验收

- A、B–E角色正确，B–E确实回复A的结构只作为本次模板排版，不冒称真实原帖关系；
- 原文能按ID回溯，B–E默认逐字保留；
- 每处替换均能映射到用户明确要求或目标品牌证据；
- 批量生成时 A 不机械重复，菜品替换有目标品牌依据；
- 不能直接使用的素材被标明原因，不混入可发布文案。

## 内置案例

- 齐庆滨江银泰用户确认案例库：`examples/qiqing-confirmed-comment-cases-20260924.md`。这批案例来自用户手动确认的20条叠楼评论，后续做齐庆评论文案时优先调用；空白 B–E 保持空白，不补造。
