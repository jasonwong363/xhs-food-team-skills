# 模板库筛选与分类规则

## 评论模板

### 角色结构

- **A 主评论**：单独成立的主楼推荐、提问或表达。用户当前提供的模板中，常见形式是直接提到品牌/品类并表达推荐或强判断。归类依据是它在评论链里的功能，不强求每条都含品牌。
- **B–E 跟评**：回复 A 的跟楼内容。常见功能包括补充体验、表达认同、追问门店/地址、表示想去或进一步推荐。B、C、D、E 可从不同来源的同类跟评中交叉搭配；不能改造出原文没有的消费经历。
- 记录来源中真实楼层和用户指定的模板角色。若评论截图不是同一条链，保留各自来源；用户组装时另标“跨来源组合”。

### 正向筛选

用户目前明确只要正向且可借鉴的评论：保留明确推荐、喜爱、认可、正面体验、正向询问/种草意向等。纯中性问句仅在用户确认要保留这类互动模板时入库。排除明确差评、负面体验、攻击、反讽、负面比较，以及正负混杂但核心态度不正向的内容。不要把“还没去/看着想去”错误记作亲自消费体验。

对正负混合评论，按完整上下文判断；无法判断时标“待确认”，不进入可调用正向库。被筛掉的原话不写入正向模板表；报告可只给筛除数量和原因类别。

### 语义标签

记录评论功能、表达强度、明确提及的菜品/品类/品牌、是否明确到店、是否明确复购、可替换实体和不可迁移事实。只能按字面证据打标，例如“去过无数次”可标明确复购；单纯“好吃”不能推断复购。

## 截流帖模板

这是面向尚未去过门店、尚未完成选择的人群的需求帖/上车帖。筛选时优先识别：城市+品类需求、提问式/求推荐式钩子、选择困难或决策门槛、评论承接空间、正文推进结构。模板用于后续按客户品牌基准最小改写；保留原来的钩子和结构，不能从模板库阶段原创新主题。

不要把封面/标题是否出现品牌名作为固定要求；按用户针对该模板的指令保留。用户已明确的截流方向中，封面可采用“杭州到底有没有好吃的牛蛙火锅”这类城市+品类提问，不强行塞门店名。关键词是否优先以城市+品类为主，具体执行按客户关键词基准和数据核验结果，不将猜测热度记录成平台数据。

## 素人笔记模板

这是面向已经到店并消费过的人群，以到店后的个人体验分享为主体。判断正文是否有明确到店、点单、用餐过程或体验表达；仅标题/标签带店名不够。记录其真实文本结构、场景、产品位置和具体口碑表达。

模板中的第一人称经历仅作为源文本结构；只有当前用户提供相应真实体验后，才可整理成当前用户的第一人称参考草稿。筛选入库不等于确认来源内容真实，也不等于适用于目标商家。该类记录的“体验依赖”标为“需要用户真实体验”。

## 跨库共用规则

- 一篇内容若同时有需求提问和到店体验，按主要叙事任务分类，可加次要标签；不要重复创建两条原始记录。
- 只可在同一库型、相近表达功能中交叉调用。截流帖不可直接当作素人体验，素人经历不可伪装成未到店提问。
- 分别记录“原文证据”“归类判断”“适配边界”，不要将推断写成用户原话。
- 热度指标是来源快照，不等于内容效果因果；缺失值留空。链接、截图或行号至少保留一种稳定来源定位方式。
