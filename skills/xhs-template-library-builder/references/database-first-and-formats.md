# 数据库调用与交付格式真源

## 2026-09-29用户明确修订

用户原话：“所有的改写都是调用数据库，筛选后改写。而不是自行生成”；“一个表格格式，你可以放到数据库里。后面可以直接调用这个格式；而不是每次都我提醒”。适用于本用户的小红书需求帖、评论和素人笔记改写，不扩展到无关写作任务。

### 必须先筛选再改写

1. 先读取本批对应数据库。默认内容库：仓库 `library/小红书模板库-叠加执行表版.xlsx`，或用户项目中更新后的同名内容库。按类型读取“调用库-截流帖”“调用库-评论”“调用库-素人笔记”；评论优先检查“用户确认模板组合”，并关联相应“审核详情”表。用户指定更新库时以更新库为准。
2. 逐条读取完整原文、来源、ID、角色和审核状态，依据目标问题、地域、品类、事实与语气筛选；先确定入选记录，再改写。关键词命中不等于适配。不得先写成稿，再找相似ID补来源。
3. 每条保留“成稿编号→库记录ID→原文→入选理由→替换项→目标事实证据→审核状态”。不得只用一两个模板自行造变体凑批次数量。合适模板可以有依据地复用，但记录复用原因；也不为了ID全量不同而选不适配模板。
4. 需求帖与素人笔记按对应skill最小替换；评论A同样先选模板，B—E默认逐字调库并逐条承接A，不能按编号轮换拼组。评论组合是参考草稿，不冒称平台真实同链或独立消费者证言。
5. 菜品评价、产品基准只供应事实与替换依据，不代替表达模板；此前“评价亮点可不匹配模板直接写A”的例外被本次要求收紧。可在已选骨架内做有依据的调整，不能另起一套原创推荐理由。
6. 库不足时交代缺口并继续筛已有来源，不编稿补数。用户新给的原稿/截图先整理为本批可追溯候选记录再筛选，不必为了入库再问一次；未经确认记录仍为待审核。以后用户明确改变本规则时，按新指令处理。

### 交付格式库

格式注册表：本 Skill 附带的 `../assets/交付格式库/格式索引.json`（相对于本参考文档）；用户项目已有更新索引时以项目索引为准。

- 默认需求帖Excel格式ID：`FMT-XHS-DEMAND-14COL-v1`。先读注册表并复制其中空白xlsx母版，不凭记忆重建，不再次索要已确认格式。
- 适用：需求帖、需求帖加A—E评论。列顺序固定为：编号、大字报内容、标题、正文、话题、发布账号、博主昵称、小红书链接、评论参考草稿（A—E）、价格、渠道、截图、抖音链接、截图。
- 标题第1行，表头第2行，数据第3行起，冻结前2行；保留母版配色、边框、列宽、合并和换行。空白样例20行不限制交付数量，按实际数量扩展或缩减并继承样式。长文本必要时增加行高，不能缩小字号挤入。
- 需求帖阶段正文D与评论I留空；评论阶段在用户最新执行表按编号回填I，其余内容保持。来源映射留同目录审计文件，不自行添加列或改成多表。
- 优先级：用户本次指定格式/最新执行表 > 已确认项目格式 > 本注册表默认母版。此母版不覆盖素人笔记飞书十列交付契约。
- 格式入库只表示格式确认，不把示例文案、门店事实或待审核成稿升级为内容确认。本母版已清空客户数据，原始齐庆参考另存只供样式溯源。
