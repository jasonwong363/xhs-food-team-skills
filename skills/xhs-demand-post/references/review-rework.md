# 用户审核返工

## 先确定本轮动作

| 用户指令 | 动作 |
|---|---|
| “记录一下”“以后不要”“更新规则” | 记录否定和适用范围，接入后续筛选；不改交付表、不生成替换稿 |
| “这些不要，重新匹配／重新生成” | 保存旧稿与反馈，再调用其他适配模板，替换指定条目 |
| 仅“这些不要／删掉” | 记录否定并从当前执行内容撤下指定稿，不自行补稿；编号保留供追溯 |
| “已经改好了”并提供修订表 | 以用户修订稿为最新基准，不重新覆盖；历史批注不自动重做 |

用户已经授权本批替换且范围明确时直接执行，不再索取原因或重复确认。仅在现有文件和上下文无法辨认批次、编号或被否定字段时询问最小缺口，暂停对应条目的写回。

## 识别旧稿并记录反馈

1. 从用户指定文件、最近交付文件和审计映射确定目标批次；编号是业务编号，不直接当 Excel 行号。
2. 以“批次＋编号＋原文”绑定反馈；有替换历史时核对 previous_version 或旧审计。用户指之前被替换的稿，就记录旧稿，不能把同编号新稿判为被否定。
3. 优先复用品牌基准链接的反馈记录。没有记录时，在品牌资料目录建立 `需求帖反馈/否定记录.json` 或 `评论反馈/否定记录.json`，并在品牌基准加入入口；可附可读 Markdown。每轮筛选前读取适用反馈，交付前再对照成稿检查。
4. 记录：反馈ID、日期、内容类型、品牌／项目、适用范围、批次文件、工作表、编号、被否定字段与完整旧原文、原模板ID与来源、用户原因（未提供为 null）、处理动作、替换稿关联和真实审核状态。缺失来源字段标未找到，不编造。重复收到同一反馈时更新同一记录，保留历史，不重复累计。
5. 默认适用于当前品牌／项目各门店；用户指定仅本批、本店或其他范围时遵从。不得扩展成所有客户通用禁用。

## 过滤与重新匹配

- 被否定的原句以及只换城市、商圈、品类、品牌、标点的近似表达均排除；核对去除这些变量后的语句结构和意思，不能只查完全重复。
- 否定事实与原因推断分开。未说明原因就记录“用户否定，原因未提供”；不把单条反馈扩大成家庭、同事、晚饭等整个场景禁用。用户明确否定某类结构时才按其范围建立类别规则。
- 通用模板库保留源记录；品牌反馈用于本项目过滤，不从总库物理删除模板，也不一律封禁该模板的所有可用表达。
- 重新匹配必须读取模板库，选择其他适配表达，保留来源映射；不得只改几个同义词或自主编造补齐数量。可用模板不足时说明真实缺口。

## 写回与完成

- 按本 Skill 原有事实、改写及交付规则执行；反馈不免除事实核验，不授权发布。
- 写 Excel 时使用电子表格 Skill。保存可恢复旧版本或旧稿审计，只改授权编号和字段；保留其他稿件、用户修订、公式、格式及工作表。批注保留并在审计注明对应旧版本已处理。
- 新稿标“待审核”；不继承旧稿“已确认”。版式没有审核列时写入同目录审计，不擅自增列。
- 回读目标条目，对照旧稿与其他条目，确认仅授权字段变化、编号不乱、模板可追溯、否定表达未回流。按原交付规则检查显示效果。
- 完成后简述记录／撤下／替换数量和待审核状态，提供文件。仅记录任务在记录落盘并接入筛选入口后结束。

## 需求帖边界

- 用户否定整条时记录封面大字和标题；只否定标题时按指令处理标题并检查封面一致性，不扩大成整稿否定。
- 正文继续为空；不生成评论。改动需求后，已有评论可能失配，在审计标“评论待重新匹配”，保留原值；待用户确认需求帖并要求评论时再交接。
