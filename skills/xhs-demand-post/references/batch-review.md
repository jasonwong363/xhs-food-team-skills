# 大字报需求帖批量检查规则

## 单条适配检查

逐条回答：

1. 这条帖子里的用户正在解决什么吃饭选择？
2. 地点、人数、预算、口味或场景中，哪些条件来自用户输入或品牌截流基准？
3. 目标商家为什么有资格进入后续评论的候选答案？
4. 如果删除品牌名，这条需求是否仍像真实用户会提出的问题？
5. 是否夹带了已到店体验、门店背书或未经核实的承诺？

第2、3项没有依据时标待核；第4项不成立时重做需求结构；第5项存在时删除或改回需求表达。

## 批量重复维度

| 维度 | 例子 |
|---|---|
| 地域层级 | 城市、行政区、商圈、商场、车站、门店附近 |
| 需求对象 | 火锅、牛蛙火锅、美蛙鱼头、聚餐餐厅 |
| 消费场景 | 朋友聚餐、同事聚会、两人吃饭、家庭聚餐、夜宵 |
| 决策条件 | 口味、预算、分量、环境、交通、停车、排队 |
| 问法 | 求推荐、二选一、避雷、第一次吃、哪里有、哪家更适合 |
| 内容结构 | 单问句、条件清单、背景＋问题、多个候选比较 |

以上维度用于记录复用情况，不自动将重复判为不合格。齐庆项目用户已于2026-09-27明确：有市场互动证据的有效模板可以重复，不要求每条不同。需区分误复制与有意复用；后者记录原模板ID、赞藏数据、适用范围和复用次数，按批次授权执行。不能为了降低重复率而添加没有真实案例支持的需求方向。

## 批量平衡

不设脱离模板库和商家条件的固定配额。根据有效模板容量分散地域层级、消费场景、决策条件、模板来源、问法，以及泛品类和垂直品类入口。

同一结构可以跨城市、跨门店及同批复用，但要验证地域与商家承接条件。“爆款”需要互动证据，不把某一篇的表现外推为整个结构的必然效果；保留同结构高低互动样本。

## Excel交付检查

- 先确认用户文件是待修改稿还是已修改参考稿；仅更新规则时不重写表格；
- 实际数据行数等于交付数量；
- 编号连续或与用户指定编号完全一致；
- 所有成稿都有模板ID映射；
- 审核状态符合实际；
- 原有批注没有丢失；
- 正文列保持空白，没有模板正文、占位符或新生成内容；
- 逐条回读话题：按 `#话题` 提取、去重后为6—10个（超过5个、不超过10个），同条不重复；
- 话题与本条封面、标题、已确认地域及品类一致；不以无关地名、场景、品牌或未经核实的卖点凑数量；
- 评论列没有新生成内容；
- 无 `#REF!`、`#VALUE!`、`#NAME?`、`#DIV/0!` 等公式错误；
- 封面大字的换行、行高和列宽在 Excel 中可读；
- 抽查首行、中间行、末行及所有有批注的行。

## 评论交接检查（本 Skill 不生成评论）

- 交接的是用户最新修订或确认的需求帖，按编号携带封面、标题、话题和内部核心需求；正文列保持空白；
- 写明品牌完整名称；齐庆项目统一“齐庆美蛙鱼头火锅”，不能后半批改简称；
- 写明品牌主要在 A、其次在 B，C—E 无品牌名及简称；仍保留 A—E 结构；
- 写明评论须逐条回应对应需求，不能仅替换店名；怕辣、两人点单、鱼头、回访等条件不能错配；
- 标黄和批注结合最新内容判断，不把已处理反馈重新执行；
- 按用户授权使用总评论模板库，包括其他品牌模板，保留来源并核验目标品牌事实；
- 后续评论任务全量核对整批，不只检查标黄行或前30条。
