# 小红书大字报需求帖筛选、改写与Excel交付

## 任务与流程位置

把已经筛选入库的大字报／需求帖模板，改写成适合目标餐饮商家的需求帖，并写入用户指定的 Excel 表格供人工审核。

```text
品牌截流基准与关键词
  → 需求帖模板筛选
  → 大字报需求帖改写
  → 写入Excel等待审核【本Skill停止】
  → 用户确认内容
  → 另行调用评论Skill匹配评论
```

“大字报”面向尚未到店、正在找店或比较选择的用户，以封面大字提出地点、场景、品类或选择需求。作者位置是潜在消费者提出需求，不把模板中的到店经历迁移成目标商家的亲历。

## 与相邻 Skill 的边界

- 品牌、产品、关键词与证据基准不完整时，先用 `xhs-food-content-positioning` 建立或补齐截流帖基准。
- 原始候选很多、尚未筛选入模板库时，先用 `xhs-benchmark-pool-screening` 或 `xhs-template-library-builder` 完成筛选和建库。
- 已真实到店、要写菜品体验与评价时，使用 `xhs-note-minimal-rewrite`，不使用本 Skill。
- 用户确认需求帖内容后，评论另用 `xhs-comment-template-rewrite`。本 Skill 不生成、改写、匹配或预填评论。
- 只需要把已确认成稿转录到飞书时，可交给 `xhs-copy-delivery`；本 Skill 的 Excel 写入属于需求帖审核流程的一部分。

## 必要输入

优先从当前会话和现有文件读取，不重复询问已经确认的信息：

1. 目标品牌及本批适用门店；
2. 品牌截流基准：可写品类、产品特色、卖点、证据与禁写边界；
3. 本批已核验关键词及其适用门店、地域层级和数据状态；
4. 可追溯的大字报模板库，至少包含模板ID、封面、标题、正文或原文、来源与审核状态；模板正文只用于理解原帖需求，不作为目标稿交付字段；
5. 数量要求；
6. 用户指定的 Excel 模板、目标工作表和保留范围。

缺少 Excel 模板时可以先交付结构化草稿，但不得声称已经写入表格。缺少品牌事实或模板库时，只指出会改变选稿和改写的最小缺口；不得凭空原创一批需求帖来补数量。

## 用户修订稿与反馈的处理

- 先依据用户本次说明识别文件用途：待修改稿、用户已修改稿，或供后续学习的参考稿。用户说“已经改好”“以后注意”“更新Skill”时，将其修订稿作为后续基准，记录规则，不再生成另一份修改版。
- 用户最新修订内容优先于此前生成版本。黄色标记和批注须结合当前单元格内容判断；历史批注可能已处理，不把仍保留的标记自动当成未完成任务。
- 只有本轮要求修改表格时才执行对应修改；用户仅要求更新规则时，只更新 Skill 及其检查规则。

## 审核返工与否定记录

每轮筛选前读取品牌／项目反馈记录，交付前排查被否定原句及近似表达。用户反馈不行、要求剔除、重新匹配或只记录时，读取 [审核返工规则](references/review-rework.md)。区分“只记录”和“修改当前稿”，按批次、编号和旧原文定位；替换稿统一待审核。

## 工作方式

### 1. 确定本批需求入口

**齐庆项目2026-09-27最新用户口径：先看真实市场案例，再定需求方向。** 区域词只说明地点，不自动推出家庭聚餐、同事约饭等配额。规划每个方向应列出实际模板ID、原始问法、可见点赞/收藏/评论数及商家适配条件。互动未显示就留空；聚光搜索指数不能替代笔记互动数据。允许重复使用有互动证据且适配的模板，不为每条不同而凭空新增场景。调研归档使用当前项目提供的资料目录；跨电脑使用时先定位同批调研资料。

从已核验关键词和门店真实位置建立本批词池，分清：城市＋品类；行政区／商圈／商场／交通节点＋美食；区域节点＋品类；以及聚餐、约会、多人、预算、口味、停车等有真实承接条件的场景需求。

候选词、聚光实测词和最终采用词必须分开。搜索指数不等于到店转化；大众点评标签不自动等于用户实际搜索词。关键词必须同时满足地域适用、需求意图和门店承接能力。

### 2. 筛选模板

逐条判断模板是否能被目标商家承接，再决定入选、待核或淘汰：

- 用户需求能否自然导向目标品类；
- 地域层级是否适用于本批门店；
- 预算、人数、营业时段、菜品、服务或环境要求是否有依据；
- 评论阶段将来是否存在自然回答空间，但本阶段不编写答案；
- 删除不适配信息后，原模板主要结构是否仍成立。

具体菜品并非商家稳定菜单、需求过窄且商家无法承接、依赖原城市独有地标或活动、把已有消费体验伪装成求推荐，或只能靠编造价格、距离、排名、服务承诺才能成立时，直接淘汰或标待核。

### 3. 建立逐条映射

每条成稿内部保留：成稿编号、模板ID与来源、原模板功能、目标需求场景、采用关键词、适用门店或地域、品牌证据ID、改写字段和审核状态。

模板原文只提供结构、语气和提问方式，不是目标品牌事实。跨城市复用时替换城市、区域和品类，并重新验证需求是否仍自然；不能只机械换地名。

### 4. 改写需求帖

默认最小改写：保留模板的句式、信息顺序、提问方式和情绪强度，只替换为本批适用的地域、品类、场景和筛选条件。

- 封面大字必须一眼看出“在哪里／什么场景／想找什么”。
- 标题继续提出同一需求，不能提前替评论回答“哪家好”。
- **话题数量：每条6—10个（超过5个、不超过10个）。** 按本条封面、标题和已确认关键词，组合适用的城市、区域／商圈、品类及需求话题；同条去重后计数，以 `#话题` 形式写入话题列。不得为了凑数量添加无关地名、场景、品牌或未经核实的卖点；品牌话题是否使用仍遵循本批品牌词规则。
- **后续大字报不生成正文。** 模板正文只用于识别需求、限制条件和评论承接方向；目标 Excel 已有“正文”列时保留列结构并保持单元格空白，不把模板正文迁移或另写成稿。
- 不写“我吃过、回购、刚吃完、服务很好”等未发生的到店体验。
- 不硬塞品牌名。需求帖本体是否出现品牌名，按用户方案和模板规则执行。
- 不把菜品好评、顾客评价或模板中的外店卖点变成求帖作者的事实。
- 不新增未经核实的价格、活动、排队、距离、排名、正宗认证、营业时间和停车承诺。
- 本轮要求处理、且尚未落实的批注为“取消”“过于具体”“不适合”时，替换整条需求方向，不在原问题上换几个同义词；用户已修订的内容按最新稿保留。

### 5. 批量控制重复

批量交付前，按 [批量检查规则](references/batch-review.md) 检查封面骨架、需求对象、地域层级、场景、限制条件、问法和结尾。数量要求不能靠仅替换城市、菜名或标点凑数。

默认消除误复制的完全重复；用户明确允许重复有效模板时，按授权复用同一结构乃至同一表达，并保留模板ID、互动证据、适配检查与本批复用次数，不强求每条都不同。数据库中的重复截图合并来源，执行稿中的有意复用不因此删除。没有市场案例支持时不擅自原创方向补齐数量。

### 6. 写入 Excel

用户要求写入 `.xlsx` 时，同时遵循 `spreadsheets` Skill：

1. 读取目标工作簿、工作表、已用区域、表头、批注、合并单元格、行列尺寸和样式；
2. 按编号匹配，不覆盖其他工作表或无关区域；用户明确要求全量替换本批内容时才覆盖对应内容列；
3. 保留已有批注、来源、状态和审核记录；
4. 正文列若已存在，保持空白；不得用说明、占位符、模板原文或自主生成内容填充；
5. 评论列若已存在，保持原值或按用户明确要求清空，不在其中写入新评论；
6. 至少保存编号、大字报内容、标题、话题、模板来源和实际审核状态；具体列按用户附表格式；
7. 写入后回读全部目标行，检查条数、编号、正文空白、换行、截断、重复、批注、公式错误和样式；
   逐条检查话题去重后数量为6—10个，且与对应需求及地域相符；不足或超限须修正后再交付。
8. 进行可视化检查，确认主要文字可读、未溢出且行高列宽合理。

用户附表格式优先于通用字段建议。不得为了增加来源列破坏用户版式；完整映射可保存在用户允许的隐藏工作表或同目录审计文件中。

## 审核状态与停止条件

首次写入统一标为真实状态，如“待审核”，不能因为已经生成就写“已确认”。完成 Excel 写入、回读和视觉检查后立即停止，并说明写入数量、仍待核事项、本轮没有处理评论，以及需要等待用户确认或批注。

只有用户明确表示需求帖已确认，并另行要求评论，才将已确认需求帖及编号交接给 `xhs-comment-template-rewrite`。本 Skill 自己仍不执行评论任务。

## 交接评论 Skill 的固定要求

交接时必须携带以下规则及用户最新修订稿；这些是后续评论任务的约束，不授权本 Skill 生成评论：

1. **品牌全称统一**：使用用户确认的完整品牌名称，整批前后保持一致，不在后半批简写。齐庆项目的全称为“齐庆美蛙鱼头火锅”；其他项目使用各自确认的全称。
2. **品牌位置限定**：品牌主要出现在 A，少量可出现在 B；C、D、E 不出现品牌名称或简称。A—E 评论结构仍保留，“A 或 B”指品牌出现位置，不是把评论数量缩减成两条。不为凑比例设固定配额。
3. **逐条主题匹配**：按编号读取封面大字、标题、话题、内部需求标签和评论，提取地点、品类、人数、口味及核心问题。A 或 B 应直接承接问题，其余跟评围绕同一需求展开；不能仅换品牌名就认定匹配。
4. **重点错配检查**：怕辣帖应回应辣度或解辣搭配，两人点单帖应围绕两人点单，鱼头帖应围绕鱼头，回头客帖应围绕回访理由或常点内容。不能拿旅游行程、赶车、停车、四人聚餐等无关讨论来填充。不得为回答回访次数而编造到店经历。
5. **全量复核**：标黄行和用户反馈行优先检查，随后核对整批；已修订标黄内容以最新文本为准，不重复套用旧批注。
6. **模板来源开放**：按用户授权调用总评论模板库，其他品牌用过的模板也可选，不限制为齐庆内置的20组。先筛主题适配，再按目标品牌事实替换；保留模板ID和来源，不迁移其他品牌的独有产品、地点、经历或服务承诺。

交接至少包含：用户最新文件与工作表、成稿编号、封面、标题、话题、内部记录的核心需求及限制条件、品牌全称、可用事实、上述品牌位置规则、指定评论模板库及待核事项。正文列保持空白。后续评论 Skill 完成后应全量检查全称、A/B位置、C—E无品牌和主题一致性。

## 完成标准

- 每条稿件能追溯到真实模板ID和品牌证据；
- 每条需求与目标门店、地域、品类和关键词相符；
- 封面和标题共同表达一个明确需求，正文列保持空白；
- 每条有6—10个不重复且相关的话题，已全量回读核验；
- 没有把素人到店体验写进需求帖；
- 批量稿件不存在只换城市、菜名或标点的机械重复；
- Excel 条数、编号、格式、批注和审核状态经回读验证；
- 评论区域没有任何由本 Skill 新生成的内容；
- 交付停在“需求帖待用户审核”。

## 输出

用户只要文案时，按编号输出需求帖字段和简短来源映射。用户指定 Excel 时，以最终工作簿为主要交付，不在聊天中重复粘贴全部文案。
